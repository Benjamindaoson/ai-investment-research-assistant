## Context

`InvestmentMemo` is already persisted inside `ResearchRun` and exposed through
the existing API. It currently has a single executive summary plus flat ID
lists. The runtime must remain deterministic until a production evidence
provider and evaluated synthesis model are promoted, and FinEvidence remains
the owner of evidence retrieval.

## Goals / Non-Goals

**Goals:**

- Add a small, typed section projection that is safe to render and export.
- Keep every section traceable to existing claims, evidence, or unresolved
  requirements.
- Preserve the existing memo status and explicit human approval path.
- Make the API change additive so existing clients continue to parse the memo.

**Non-Goals:**

- Long-form LLM writing, valuation, or new financial data retrieval.
- A second persistence table or a document/RAG subsystem.
- Inventing section content when the run has no qualified evidence.

## Decisions

1. Use a `MemoSection` value object with a closed `section_key` set: `thesis`,
   `evidence`, `risks`, `scenarios`, and `decision`. These are the minimum
   review surfaces already produced by the runtime; a free-form key would make
   evaluation and clients brittle.
2. Generate sections from the run's existing thesis, claims, evidence, and
   unresolved requirements. Each body is count- or statement-based and carries
   links; no new factual source is created.
3. Persist sections in the run payload and validate them with the existing
   Pydantic/Zod boundaries. This keeps checkpoint/resume and read-back on one
   source of truth.

## Risks / Trade-offs

- [Risk] The deterministic text is not a polished IC narrative → Mitigation:
  label the memo as a review projection and leave rich synthesis behind the
  evidence/provider promotion gate.
- [Risk] Adding a required field breaks old stored runs → Mitigation: use a
  default empty list during model validation; all newly generated memos contain
  the complete section set.

## Migration Plan

New runs write sections immediately. Existing SQLite payloads remain readable
because the field defaults to an empty list; they can be regenerated by a new
execution if needed. No destructive migration is required.

## Open Questions

The exact institutional memo template (for example, sector-specific financial
and valuation sections) belongs after real evidence schemas and should be added
as versioned section templates rather than hard-coded here.
